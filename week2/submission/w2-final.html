W2-Final — EASY-RAG

Exercise 1's EASY-ASSISTANT grown into a real RAG app: FastAPI backend, plain-JS frontend, documents ingested into a per-assistant collection through the course's collections-manager (vendored as a path dependency — the app never talks to ChromaDB directly), answers grounded in retrieved chunks with visible provenance. Models: qwen3:1.7b answers (run locally as qwen3-fast — the same weights pinned to 6 CPU threads), nomic-embed-text embeds, both on local Ollama.

How ingestion and retrieval flow

UPLOAD  file ──markitdown──► markdown ──chunk (sections | chars fallback)──► embed ──► assistant's collection
             ├─► data/static/<assistant>/<doc>/original        (linked from every answer)
             └─► data/static/<assistant>/<doc>/original.ext.md  (the distillation the chunks came from)
             every chunk carries: source doc, chunk number, title, doc/md URLs, strategy, ingestion date

CHAT    question ──embed──► query collection ──► top-K chunks with similarity ──► gate: similarity ≥ threshold?
             ├─ some pass ──► format with provenance ──► fill {context}/{user_input} ──► LLM ──► answer + sources + usage
             └─ none pass ──► honest refusal, generated locally — the LLM is never called (usage stays empty)

The three knobs, and why

knobvaluewhy
chunking sections (level 2), falling back to chars 800/100 In exercise 3 I ingested the same document both ways: section chunks carry their own heading and one complete idea, retrieved the exact right section every time (0.675 vs 0.623 on the same question) and kept the model from inventing facts out of window fragments — the fallback covers documents that convert without headings.
K 4 Enough for an answer that spans a couple of sections, while keeping the prompt small for a 1.7B model — with section-sized chunks, K=4 already means ~2k prompt tokens.
threshold 0.57 Calibrated in exercise 3 against nomic-embed-text and my documents: off-topic questions peaked at 0.552 (not near zero!) and real questions started at 0.608, so 0.57 sits inside the narrow band that blocks noise without starving real answers.

All three are .env configuration, not constants — the threshold in particular is a calibration that belongs to this embeddings model and corpus, not a universal number.

Honest refusal

prompt_tokens, compared with exercise 1

In exercise 1 my prompt_tokens went 968 → 1,007 turn over turn with a single 3,193-character document — the whole file rode along every time, so the prompt could only grow with the knowledge. EASY-RAG holds a 104,000-character corpus (4 documents, 56 chunks) and the same questions cost 372–827 prompt tokens — and when the corpus grew from 3 documents to 4, those numbers did not move by a single token, because only the retrieved chunks travel: the prompt scales with the question, not with the corpus — a corpus ~32× larger than exercise 1's document produced prompts of the same size or smaller, and that is the reason this week existed.
